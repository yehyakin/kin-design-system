这些行指向稳定的规范合同。稳定状态记录行为与证据，但不代表存在通用运行时组件包。

证据列表（Evidence List） 把结论或决策与支持、缺失、过期和冲突的来源建立对应关系。 稳定合同 检查 → 建议变更审核（Suggested Change Review） 在接受、拒绝或编辑变更前，对比当前值与建议值。 稳定合同 检查 → 执行预览（Execution Preview） 执行前展示目标、写入、权限、外部影响、不可逆性与回滚。 稳定合同 检查 → 后台任务队列（Background Task Queue） 让已接受的持久任务在进度、取消、恢复与结果阶段始终可识别。 稳定合同 检查 →

打开文档 →

规范合同、生成的互操作文件、固定参考界面与验证记录属于不同证据层，不互相替代。

设计原则与视觉特征 任务优先、单一主导区域、连续结构、语义分离与有目的的动效。 规范 阅读 → 基础与语义 Token 主题、对比度、字体、间距、表面、焦点和生成的互操作输出。 合同 + 生成文件 检查 → AI 交互合同 结论、依据、不确定性、范围、人工批准、审计与回滚分别表达。 规范 阅读 → 编码工具交付 固定经过评审的合同，并明确保留项目自己的路由、数据、实现、证据与回滚。 Contract-first 使用 → 页面与工作流合同 完整用户任务、状态族、响应式行为、返回上下文与产品后端责任边界。 目录支持 浏览 →
